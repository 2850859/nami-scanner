# （以下）cleartrade レガシー仕様 — `strategy_rules="cleartrade"` 時のみ

## 1. ユニバース定義

| 項目 | 条件 |
|------|------|
| 市場 | 東証プライム or スタンダード |
| 時価総額 | 3,000億円 〜 3兆円 |
| 平均売買代金 | 50億円 / 日 以上（20日平均） |

## 2. スクリーニング条件（全AND）

| # | 条件 | 計算式 |
|---|------|--------|
| S1 | 出来高急増 | `当日出来高 / SMA(出来高, 20) ≥ 2.0` |
| S2 | ブレイク | `終値 ≥ MAX(高値, 20)` |
| S3 | モメンタム | `(終値 / 終値[20日前]) - 1 ≥ 0.05` |

## 3. トレンドフィルター（全AND）

| # | 条件 |
|---|------|
| T1 | `銘柄終値 > SMA(終値, 20)` |
| T2 | `TOPIX終値 > SMA(TOPIX終値, 20)` |
| T3 | **パーフェクトオーダー**（日足）: `SMA(終値, 5) > SMA(終値, 10) > SMA(終値, 20)` |

検証・比較時は `StrategyConfig.require_perfect_order=False` または CLI `--no-perfect-order` で T3 を無効化可能。

## 4. 押し目検出

スクリーニング通過後、以下を全て満たす日に「押し目成立」：

**実装上の解釈（`backtest_engine.py`）**  
「通過後」を **同一営業日に限定しない**。過去 `screen_recent_days`（既定20）営業日以内に、セクション2〜3のスクリーニング（S1〜S3・T1・T2）を一度満たしたあと、**別の日**で下記 P とエントリートリガーを判定する。  
（同日に「20日高値ブレイク」と「10日高値から−3〜−5%押し」を両立させると、ほぼ矛盾するため。）

| # | 条件 | 計算式 |
|---|------|--------|
| P1 | 押し目幅 | `-5% ≤ (終値 / MAX(高値, 10)) - 1 ≤ -3%` |
| P2 | 出来高収縮 | `SMA(出来高, 5) < 0.7 × 直近ピーク日出来高` |

**P2 の「ピーク日出来高」の実装**（`StrategyConfig`）  
- `use_strict_peak_day=True` … 表どおり「出来高最大日と高値最大日が同一日」のときの出来高（厳格・シグナル稀）  
- `use_strict_peak_day=False`（既定）… 窓内で最も新しい「高値＝期間高値」となった日の出来高（検証用に実用的）  
| P3 | 価格位置 | `終値 ≥ SMA(終値, 20)` |

**直近ピーク日の定義**：過去20日のうち、出来高最大日 **かつ** 価格高値日（両方満たす日）。同一日でない場合はその期間で押し目シグナルを発生させない（厳密化のため）。

## 5. エントリートリガー（OR条件）

押し目成立後、以下のいずれかが発生した日の翌営業日寄付で成行買い：

| # | トリガー |
|---|---------|
| E1 | 終値が前日高値を上抜け |
| E2 | 陽線包み足（当日始値 < 前日終値 かつ 当日終値 > 前日始値 かつ 当日終値 > 当日始値） |

## 6. エグジット

| 種類 | 条件 | アクション |
|------|------|-----------|
| 損切り | 終値 ≤ エントリー価格 × 0.95 | 翌寄付で全決済 |
| 第一利確 | 終値 ≥ エントリー価格 × 1.10 | 翌寄付で50%決済 |
| トレーリング | 終値 < MAX(SMA(終値,5), エントリー価格) | 翌寄付で残り全決済 |

※第一利確後は「5日線 or 建値」の高い方をストップとして使用。

## 7. ポジション管理

| 項目 | 値 |
|------|-----|
| 1トレードリスク | 総資産の0.1% 〜 0.25% |
| ポジションサイズ計算 | `(総資産 × リスク%) / (エントリー価格 × 0.05)` 株数 |
| 最大同時保有 | 3銘柄 |
| 枠フル時の処理 | シグナル強度スコアで上位3銘柄を常に保有（弱いものを入れ替え） |

**シグナル強度スコア**：
```
score = 0.4 × (出来高倍率 - 2.0) 
      + 0.3 × (20日リターン - 0.05) × 10
      + 0.3 × (1 - |押し目幅 + 0.04| / 0.01)
```
（押し目幅は-4%が最高スコア、出来高倍率と20日リターンが大きいほど高スコア）

## 8. 除外ルール

エントリー判定時、以下のいずれかに該当する場合はスキップ：

- 決算発表まで3営業日以内
- 当日のギャップアップが+5%以上（`始値 / 前日終値 - 1 ≥ 0.05`）
- 当日が陰線かつ出来高増加（`終値 < 始値` かつ `出来高 > SMA(出来高,20)`）

## 9. バックテスト設定

| 項目 | 値 |
|------|-----|
| 期間 | 過去3年（直近終了日から起算） |
| 初期資金 | 10,000万円（1億円）想定 |
| スリッページ | 0.1% |
| 手数料 | 0.05%（往復） |
| ベンチマーク | TOPIX |

## 10. 評価指標

- 総リターン / 年率リターン
- 最大ドローダウン
- 勝率
- 平均リスクリワード比
- プロフィットファクター
- シャープレシオ

## 11. 期待水準（目安）

- リスクリワード: 1.5〜2.0
- プロフィットファクター: 1.2〜1.6

## 13. 改善版ルール（指示書反映・`backtest_engine.py` 実装）

以下は改善指示書に基づく**現行実装**の要約。旧セクション4〜6の一部は置き換え。

### 13.1 押し目 P1（ATR、既定）

- `ATR = ATR(14)`（Wilder 平滑）
- `pullback_depth = MAX(高値,10) − 終値`
- 押し目成立: `1.0×ATR ≤ pullback_depth ≤ 1.5×ATR`
- レガシー固定%押し目は `StrategyConfig.use_atr_pullback=False` で従来どおり（−3%〜−5%）

### 13.2 エントリートリガー（E1/E2 + 出来高再拡大）

- E1・E2 は従来どおり（OR）
- **追加**: `当日出来高 ≥ 前日出来高 × 1.20`（`volume_reexpand_ratio`）
- 検証用に `--no-volume-reexpand` で無効化可能（`require_volume_reexpand=False`）

### 13.3 エントリー価格モード（バックテスト比較）

| モード | 意味 |
|--------|------|
| `next_open` | トリガー翌営業日寄り（スリッページ込み） |
| `close` | トリガー当日引け |
| `next_vwap` | 翌日 typical price `(H+L+C)/3` を VWAP 代理（列 `vwap` があればそれを優先） |

CLI: `--entry-mode compare` で 3 モードを連続実行し JSON の `compare` に集約。

### 13.4 エグジット（更新）

**損切り（翌寄り・全決済）** — どちらかで発動:

- `終値 ≤ エントリー価格 × 0.95`
- `終値 < 押し目形成時の直近安値`（トリガー日までの過去10営業日の安値の最小）

**第一利確**: `高値 ≥ エントリー × 1.10` で翌寄りに **50%** 決済。

**残りトレーリング**: 第一利確後、`終値 < SMA(5)` で残り全決済（建値ストップは廃止）。

**最大保有**: エントリーから **15 営業日** で翌寄りに全決済。

### 13.5 セクターフィルター（任意）

- `sector_filter_enabled=True` かつ `--sector-filter` 時:  
  **同一セクター内の上昇銘柄割合 ≥ 0.5**（バックテスト対象銘柄のみで算出）**または** セクター代表 ETF（米株はセクター名→XLK 等）終値 > その20日線。  
  日本株（`.T`）で ETF が取れない場合は TOPIX をセクター指数代理に使用。
- yfinance の `info['sector']` で銘柄をグループ化（レート制限あり）。

### 13.6 日次スキャナー連携（`scan_jpx400.py`）

- 日足スキャン時に OHLCV を取得し、`trade_rules_candidate`・`cleartrade_bonus`・`cleartrade_flags`・`eligible_trade_book`（`rank ∈ {S,A}` かつ candidate）を付与。
- cleartrade 加点後にランク閾値を 80/60/40 に再計算。

### 13.7 バックテスト出力（CSV）

`python -m trade_rules.run_cleartrade_yfinance ... --out-dir results --prefix cleartrade`

| ファイル | 内容 |
|----------|------|
| `{prefix}_metrics.csv` | 総トレード数・勝率・平均利益率・平均損失率・RR・PF・最大DD・年率・平均保有日数・最大連敗・平均スリッページ仮定 等 |
| `{prefix}_trades.csv` | 銘柄別トレード明細（部分利確は行分割） |
| `{prefix}_by_symbol.csv` | 銘柄別集計 |
| `{prefix}_by_sector.csv` | セクター別（`--sector-filter` 時に sector マップあり） |
| `{prefix}_monthly.csv` | 月別損益 |
| `{prefix}_by_regime.csv` | エントリー日の TOPIX レジーム別（bull / bear / sideways） |

### 13.8 改善前後レポート

- 旧 JSON（`metrics` を含む）を保存しておき、`--compare-baseline path/to/old.json` で `{prefix}_comparison_vs_baseline.md` を生成。

### 13.9 パーフェクトオーダー（T3）

- スクリーニング・エントリー判定の両方で `SMA(5) > SMA(10) > SMA(20)` を要求（`require_perfect_order=True` が既定）。
- 診断時は `--no-perfect-order` で無効化。

### 13.10 検証上の注意

- **ATR + 出来高再拡大 + パーフェクトオーダー**は厳しく、銘柄・期間によってシグナル0になりやすい。診断時は `--no-atr-pullback` / `--no-volume-reexpand` / `--no-perfect-order` を併用可。
- 複数銘柄バックテストは **全銘柄の共通取引日** に合わせてスライスするため、片方にだけ存在したシグナル日は消える場合がある。
